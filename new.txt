**You are extremely close!**  
The error is now crystal clear from your Nginx error log:

```
stat() "/opt/ER_Linux/frontend/build/static/css/main.f36f01c9.chunk.css" failed (13: Permission denied)
```

This means **Nginx does not have permission to traverse one of the parent directories** of your static files, even though the files themselves are readable.

---

## **How to Fix: Directory Traversal Permissions**

Nginx (running as `www-data`) must have **execute (`x`) permission on every parent directory** in the path `/opt/ER_Linux/frontend/build/static/css/`.

### **Run these commands:**

```bash
sudo chmod o+x /opt
sudo chmod o+x /opt/ER_Linux
sudo chmod o+x /opt/ER_Linux/frontend
sudo chmod o+x /opt/ER_Linux/frontend/build
sudo chmod o+x /opt/ER_Linux/frontend/build/static
sudo chmod o+x /opt/ER_Linux/frontend/build/static/css
sudo chmod o+x /opt/ER_Linux/frontend/build/static/js
```

- The `o+x` means "others can enter/traverse this directory".
- This does **not** make files world-readable (they already are), it just allows Nginx to walk the directory tree.

---

## **After Running the Above**

1. **No need to reload Nginx** (permissions are checked at runtime).
2. Refresh your browser and your static files should now load **without 404s**.

---

## **Summary**

- The files exist and are readable.
- The error is due to missing `x` (traverse) permission on one or more parent directories.
- The above commands will fix it.
